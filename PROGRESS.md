# Progress

What has been built, one line per feature, in the order it landed.

## Log

- [T01] Repo skeleton: uv project, `offer-engine` CLI that finds subcommands in `offer_engine/commands/`, `.env` settings (`uv run offer-engine --help`, `uv run offer-engine check-env`, `uv run pytest`)
- [T02] Shared types in `domain.py`, SQLite schema and migrations, Simulation Clock, versioned Rules store, Ground Truth boundary test (`uv run offer-engine db init`, `uv run offer-engine clock show`, `uv run offer-engine clock advance --days 1`)
- [T05] Generator: 5 categories, 200 products, Customers with hidden traits and 12 months of organic events from `simulate_day`, the same for a seed (`uv run offer-engine generate --customers 200 --seed 7`)
- [T06] Rules engine: Eligible Set for one Customer with a Binding Rule per limit; Opt-out, Holdout, Fatigue Pause, frequency cap, cooldown and eligibility short-circuit to No Offer (`uv run offer-engine eligible --demo`)
- [T07] Validation: `validate` recomputes the Eligible Set and reports every Rule a Proposal breaks, plus a hypothesis property test that 500 random rule-breaking Proposals never pass (`uv run pytest tests/test_validation.py tests/test_validation_property.py -q --hypothesis-show-statistics`)
- [T08] Caption Check: rejects captions with numbers or deadlines that differ from the Offer, invented urgency, unoffered promises, over 280 characters or blank; 65 bad and 20 good captions in `tests/data/captions.jsonl` (`uv run offer-engine caption-check "Hurry, 30% off tonight only!" --offer-type pct_category --param pct=15 --param cap=300 --category fashion`)
- [T09] Decision pipeline: `decide` runs the Rules, the rules chooser, Validation and the Fallback, logs the Decision and queues the Offer. Also the Customer loader, the weekly budget, `trigger cart-abandoned`, `decisions` and `eligible --customer` (`uv run offer-engine generate --customers 200 && uv run offer-engine trigger cart-abandoned C00042 && uv run offer-engine decisions --last 5`)
- [T12] Ground Truth: `generate` stores a hidden response formula per Customer and Offer Type in `sim_ground_truth` and a Response Class in `sim_response_class`; shares land in calibration target 9 (`uv run offer-engine generate --customers 2000 && uv run offer-engine ground-truth summary`)
- [T11] Agent chooser: Claude picks one option or No Offer for chat-attached Customers and writes the caption and reason; Validation now runs the Caption Check, and an invalid pick or API failure falls back to the rules chooser with the agent's raw answer stored on the Decision (`uv run offer-engine generate --customers 200`, add a `chats` row for C00042, then `ANTHROPIC_API_KEY=bad uv run offer-engine trigger cart-abandoned C00042` shows `chooser=fallback`)
- [T13] Generator at 10k scale: 10k Customers × 12 months generate in about 80 s and `simulate_day` for 10k takes under 1 s, with slow tests for both and for the calibration of a 2,000-Customer run (`time uv run offer-engine generate --customers 10000 --months 12`, `uv run pytest -m slow tests/sim/test_generate_scale.py`)
- [T14] Random past Offers in the generated history: 30% of abandoned carts, 45-day gaps and Friday broadcasts get a random Offer (none to the Holdout), settled by Ground Truth into Claims, Redemptions with real orders, dismissals and Opt-outs; each Offer decides whether the Customer buys in the 7 days after it (`uv run offer-engine generate --customers 2000 && uv run offer-engine history summary`)
- [T17] Live world day-step: `clock advance` runs organic events for every Customer hour by hour, delivers history's pending orders, marks Offers to Customers without a chat `sent` at `send_at`, and calls the outcomes, Triggers and Daily Sweep hooks (no-ops until T18–T20). One day for 10k Customers takes about 1.5 s (`uv run offer-engine generate --customers 10000 && uv run offer-engine clock advance --days 1`, `uv run pytest tests/sim/test_day_step.py`)
- [T03] `offer-engine setup` walks through creating the Offer Bot and 6–8 Customer Bots in BotFather, checks each token with `getMe`, and fills `.env` with mode 0600 (`uv run offer-engine setup`; re-run it to keep or replace values)
- [T04] Offer Card PNG drawn from an Offer; Offer Bot sends a demo card on `/start` and acknowledges `/claim CODE`; first Customer Bot claims cards it receives; `offer-engine start` runs both bots (`uv run offer-engine start`, then `/start` to the Offer Bot; `uv run offer-engine demo-send` for the Customer Bot)
- [T19] Event Triggers: each simulated hour, an abandoned cart, points expiring within 7 days, 45 days since the last order and a first delivery each run the decision pipeline once per underlying event (`trigger_log`), and `clock advance` counts them as `decisions.<trigger>`. `trigger cart-abandoned` uses the same de-duplication (`uv run offer-engine generate --customers 10000 && uv run offer-engine clock advance --days 1 && uv run offer-engine decisions --last 10`)
- [T10] Offer delivery and Customer responses: the Offer Bot sends due queued Offers to chat-attached Customers every 5 s as Offer Cards with Claim / Not now / Stop; buttons and `/claim`, `/notnow`, `/stop` text commands update Offers, opt-outs and events, and `/start` opts back in; `chats link`/`chats list` attach Customer Bots; `outbox` messages are sent too; `demo-send` and the hard-coded demo card are gone (`uv run offer-engine chats link C00042 --bot @<customer bot>`, `uv run offer-engine start`, then `uv run offer-engine trigger cart-abandoned C00042`)
- [T15] Calibration check: `offer-engine calibrate` prints every calibration target the generated history can express, with its value, range and verdict; `--strict` exits 1 on a miss other than a category split. The generator is retuned so the 10k default world meets all but the recorded misses (`uv run offer-engine generate --customers 10000 && uv run offer-engine calibrate`)
- [T16] Estimated Lift v1 per segment (loyalty tier × days since the last order × coupon user) and Offer Type, learned from the history's random past Offers against comparable no-offer moments. Once fitted, the rules chooser and the agent rank options by it (`uv run offer-engine lift fit && uv run offer-engine lift show C00042`, then `uv run offer-engine trigger cart-abandoned C00042` gives a reason with "Lift … (estimated)").
- [T20] Daily Sweep: at 10:00 each simulated day the pipeline decides for every Customer not decided in the last 24 simulated hours, chat-attached ones first and the rest in a date-seeded shuffle. `pipeline.decide_many` loads the Rules, catalog and budget once, so 10k Customers take about 30 s. `clock advance` prints `sweep.offer`, `sweep.no_offer`, `sweep.skipped` and `sweep.binding.<rule>` (`uv run offer-engine generate --customers 10000 && uv run offer-engine clock advance --days 1`)
- [chore] `decide_many` loads Estimated Lift once per sweep, not once per Customer (an interaction of T16 and T20 found at merge; `uv run pytest tests/test_pipeline.py -k loads_estimated`)
- [T21] Streamlit console: Simulation Clock page with +1 hour, +1 day and Auto mode, and a Decision log with filters and the selected row's Offer; `offer-engine start` also runs it (`uv run offer-engine generate --customers 2000 && uv run streamlit run console/app.py`, press **+1 day**, then open Decision log)
- [T18] Offer outcomes: each simulated hour, sent Offers resolve by Ground Truth. A Customer without a chat buys with chance `p_buy`, claims first, and the order and `offer_redeemed` events link to the Offer; 25% of non-buyers claim, a few dismiss or opt out, and the rest expire. A Tester's Claim leads to a purchase with chance p / (p + 0.25 · (1 − p)), and the Offer Bot then sends "Simulated order: ₹1,240 basket, code POE-… used. You saved ₹186." Customer Bot Offers wait for a role-play fate in `sim_offer_fates`. Organic orders stop from the send until the Redemption, or for 7 days without one (`uv run offer-engine clock advance --days 4` prints `claimed`, `redeemed` and `expired`; `uv run pytest tests/sim/test_outcomes.py`)
- [T22] Console Rules page: every Rule as a plain-English form, versions with who/when and changed fields, one-click revert, the budget mode toggle with its overspend warning, a Holdout warning, and an emergency withdraw that marks outstanding Offers `withdrawn` and notifies their chats (`uv run streamlit run console/app.py`, open Rules, set the margin floor to 10 as "Asha" and save, then `uv run offer-engine trigger cart-abandoned C00042` shows `rule v1`)


## Known issues / cuts

- `uv run ruff check .` reports 5 findings in `tickets/board.py` and `tickets/test_board.py` under ruff 0.17's default rules. `src/` and `tests/` are clean (`uv run ruff check src tests`).
- `offer-engine generate` deletes all Offers, Decisions and chat links and resets the Simulation Clock. Run it before linking Customer Bots or Testers, not after.
- `offer-engine calibrate --strict` fails on the 10k default world. Past Offers miss targets 3, 3a and 4, and points breakage is 35.6% against 25–35%: 40% of new Customers never order, and their 100 welcome points always expire. Grocery buyers order about 6 times a year against the judgement split's 24–40. Details are in T15's ticket under Done as built.
- Fatigue Pause counts from each dismissed Offer's creation time, since Offers don't record when they were dismissed.
- Validation needs a `send_at` on every Offer. The Fallback (T09) must set one, e.g. the start of the send window.
- The Caption Check misses a caption that names the wrong category ("15% off electronics" on a fashion Offer); the ticket has no reason code for it. It also lets "today" and "this week" through unless worded as a deadline ("today only", "this weekend"). Add rows to the tables in `caption_check.py` to tighten it.
- The rules chooser values every category the Customer saw in the last 90 days and picks the most valuable one. A Customer who abandoned groceries can get a fashion Offer. It uses the Lift priors in `choosers/priors.py` until `offer-engine lift fit` has run.
- `uv run pytest` takes about 45 s. The Ground Truth and past-Offer tests share a 2,000-Customer world, about 18 s of that. `uv run pytest -m slow tests/sim` takes about 2.5 minutes.
- T11's live test (`uv run pytest -m live tests/test_agent_live.py`) hasn't run: it needs `ANTHROPIC_API_KEY` and `OFFER_AGENT_MODEL` in `.env`.
- The agent chooser doesn't use forced `tool_choice` (current models reject it with a 400). A reply without the tool call falls back to the rules chooser.
- Past Offers miss calibration targets 3, 3a and 4 (docs/QnA.md Q41). On 10k Customers 15% of targeted sends and 4% of broadcasts are redeemed (targets 1.5–5% and 0.1–1%), carts are recovered 28% of the time (8–15%), and 97% of those Customers would have bought anyway (45–75%). Every Customer reads every Offer and every buyer uses the code, while the benchmarks count unread messages. T16 learns from 7-day purchase rates, which this doesn't affect.
- Past Offers use the stored Ground Truth's Lift with the base at each moment; the stored `base` is still the end-of-history one.
- In the organic history, a points burn can come before, in time, the same day's delivery points it spends: `simulate_day` credits deliveries at the start of the day. Balances and expiries are right. T14's points replay fixes it for the Customers it rebuilds.
- `clock advance` on a 10k-Customer world gives about 3,200 sessions and 47 orders a day in early December, lower than T17's example. That is the calibrated rate: about 4.5 orders per active Customer a year, and most Customers have lapsed.
- For the same reason the first `clock advance --days 1` on 10k Customers fires about 150 cart-abandoned and 15 long-gap Decisions, not T19's example of 1,130 and 64. It also fires about 120 points-expiring Decisions in its first hour, one for every Customer whose points already expire within 7 days.
- `tests/sim/test_day_step.py` stubs the Triggers hook so its checks on the world's events and Offers stay exact. `tests/test_triggers.py` and `tests/sim/test_triggers_world.py` test the Triggers.
- When Telegram can't be reached, `offer-engine setup` treats every token as bad and keeps asking. Stop it with Ctrl-C; finished steps stay saved.
- The demo `/start` links the Tester's chat to Customer `C00001` itself, so the latest Tester to `/start` takes over that Customer. T25 adds per-Tester copies.
- A send Telegram refuses (e.g. a chat that blocked the Offer Bot) stays queued and logs a warning every 5 s until the Offer expires. Queued Offers past expiry become `expired` on the next hour of `clock advance`.
- `chats link` takes a Customer Bot's chat ID from the number before the colon in its bot token, so it makes no Telegram call. It would break if Telegram changed the token format.
- Estimated Lift per segment is noisy. True Lift is 1–3 points, but each segment has about 200 past Offers per Offer Type, so its estimate has a standard error of 3–5 points. The rules chooser can pick an Offer Type on noise: on 5,000 Customers, C00042's segment gets 7.8% for a points multiplier, while its mean Ground Truth max Lift is under 1%. Across segments the estimates correlate with Ground Truth at 0.29. Shrinking each segment toward its Offer Type average, or T32's uplift learner, would help.
- Nothing refits Estimated Lift on its own. `offer-engine generate` deletes the old fit, and the choosers use the priors until `offer-engine lift fit` runs again.
- The first Daily Sweep on 10k Customers queues about 8,400 Offers, 7,970 of them Nudges. A Nudge costs ₹0, so the rules chooser always finds it worth sending. The frequency cap stops repeats on later days. T16's Estimated Lift or a Rule on Nudges would change this.
- `tests/sim/test_day_step.py` stubs the Daily Sweep hook too, so its 10k-Customer day still measures the world alone (about 5 s). `tests/test_daily_sweep.py` tests the sweep, with a slow 10k test (`uv run pytest -m slow tests/test_daily_sweep.py`).
- `streamlit.testing.v1.AppTest` drops sidebar elements after a session's first run when the app uses `st.navigation`. `tests/console/test_pages.py` reads the sidebar's simulated time from a new session. The real console shows it on every run.
- A Customer Bot's Offers don't resolve until T24 writes their fates. Until then they only expire, and the Customer places no organic orders while one is sent or claimed.
- A redemption order earns points on delivery (multiplied for a points Offer) but never burns points.
- A Tester who claims and doesn't buy hears nothing. The Offer expires quietly.
- Organic orders drawn for the send day after the send, or for a Redemption day before the Redemption, become abandoned carts. Those carts reach the cart-abandoned Trigger, which the Customer's active Offer usually blocks.
- Dismissed Offers keep the status `dismissed` after expiry, so the Fatigue Pause still counts them.
